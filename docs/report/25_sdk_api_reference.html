Report 25 — RSP SDK API 说明与使用指南

Date: 2026-06-10 | Scope: 完整 API 文档、使用示范与注意事项
本文档覆盖当前 rsp SDK 的全部公开接口，包括 5 个核心类（RSPDataset、RSPConfig、RSPRunner、RSPCaseResult、RSPResult）的使用说明、代码示例与数据流关系。

1. SDK 概览

类职责一句话说明
RSPDataset 数据容器 从磁盘目录或内存数组导入路网、行程时间样本和 OD 对，自动校验
RSPConfig 实验配置 强类型配置对象：哪些 solver、哪些 alpha、repeat/OD 范围、求解器参数
RSPRunner 实验运行 单个 case 调试（solve_case）或批量实验（run）
RSPCaseResult 单 case 结果 一个 (repeat, OD, alpha) 的 tau、solver 返回值、metrics
RSPResult 批量结果 DataFrame 包装，提供 summary/accuracy/comparison/worst_cases 等聚合读取
导入方式：所有公开类统一从 from rsp import ... 导入。前提是项目根目录（/home/kkk/projects/RSP）在 sys.path 中。 
from rsp import (
    RSPCaseResult,
    RSPConfig,
    RSPDataset,
    RSPResult,
    RSPRunner,
)

2. 核心数据流

RSPDataset  ──→  RSPRunner(dataset, config)
                    ├── solve_case(repeat, od_idx, alpha)  ──→  RSPCaseResult
                    │       └── 内部调用: compute_deadline() → solve_ilp / solve_milp / solve_dijkstra
                    └── run(progress=True)                  ──→  RSPResult
                            └── 对 (repeat × OD × alpha) 循环调用 solve_case

3. 各接口详细说明

3.1 RSPDataset — 数据容器

构造方法：4 种加载方式
方法用途参数
RSPDataset.from_directory(path) 最常用：加载预生成的数据目录 path: 包含 network.npz + travel_times.npz + od_pairs.npy + meta.yaml 的目录
RSPDataset.from_files(net, tts, ods, meta=None) 从明确文件路径加载 4 个独立文件路径
RSPDataset.from_arrays(network, travel_times, od_pairs, meta=None) 从内存构建（无文件） network: RoadNetwork 或 nx.DiGraph；travel_times: 2D/3D ndarray 或 ndarray list；od_pairs: (int,int) 列表
RSPDataset.from_networkx(graph, travel_times, od_pairs, edge_order=None) 从 NetworkX 图构建，可自定义边顺序 graph: nx.DiGraph；edge_order: 可选，冻结尾部列对应
属性
属性类型说明
dataset.networkRoadNetwork路网对象（内部带 nx.DiGraph）
dataset.travel_timeslist[np.ndarray]每个元素是一个 repeat 的 W 矩阵，shape (N, E)
dataset.od_pairslist[tuple[int,int]]OD 对列表
dataset.metadict数据生成元信息（seed, CV 范围等）
dataset.edge_orderlist[tuple[int,int]]冻结的边顺序，travel_times[:, j] 对应该列表的第 j 条边
dataset.num_repeatsintrepeat 数量 = len(travel_times)
dataset.num_od_pairsintOD 对数量
示例 
# 方式 A：从预生成目录加载
dataset = RSPDataset.from_directory("Cao_SOTA_MP/data/small")
print(dataset.network.num_nodes)    # 10
print(dataset.network.num_edges)    # 20
print(dataset.num_repeats)          # 3
print(dataset.travel_times[0].shape) # (50, 20) — 50 samples × 20 edges

# 方式 B：从内存构建
import networkx as nx
import numpy as np

G = nx.DiGraph()
G.add_edge(0, 1)
G.add_edge(0, 2)
G.add_edge(1, 3)
G.add_edge(2, 3)

rng = np.random.default_rng(42)
W = rng.lognormal(mean=3.0, sigma=0.5, size=(100, 4))

dataset = RSPDataset.from_arrays(
    network=G,
    travel_times=W,
    od_pairs=[(0, 3)],
    meta={"description": "toy diamond"},
)

# 校验在构造时自动运行，确保：
#   - W 列数 == E（边数）
#   - OD 节点存在于网络中
#   - 所有 OD 对可达
dataset.save(path) — 落盘为标准目录格式

3.2 RSPConfig — 实验配置

构造函数 
from rsp import RSPConfig

config = RSPConfig(
    methods=("ILP", "MILP", "Dijkstra"),  # 启用哪些求解器
    alphas=(0.5, 0.7, 0.9),              # deadline 等级 α ∈ [0, 1]
    num_repeats=None,                      # None = 使用数据集中的全部 repeat
    num_od_pairs=None,                    # None = 使用数据集中的全部 OD
    solver_backend="SCIP",               # SCIP / CBC / GLPK
    time_limit=60,                       # 每个 job 的超时秒数
    deadline_mode="heuristic",           # heuristic / exact
    max_candidate_paths=1000,            # τ 计算的候选路径池上限
    random_seed=42,
)
print(config.expected_job_count) # None（num_repeats/num_od_pairs 未限定时）
配置参数全表
参数类型默认值说明
methodstuple[str]("ILP","MILP","Dijkstra")只能包含 ILP / MILP / Dijkstra
alphastuple[float](0.5, 0.7, 0.9)每个值必须在 [0, 1]
num_repeatsint | NoneNoneNone 表示用完所有 repeat
num_od_pairsint | NoneNoneNone 表示用完所有 OD
solver_backendstr"SCIP"推荐 SCIP（开源、稳定、快）
big_mfloat1_000_000ILP big-M 上界（实际使用更紧的逐样本 Mᵢ）
time_limitint60单 job 求解超时（秒）
deadline_modestr"heuristic"候选路径生成方式
deadline_enumeration_cutoffint15exact 模式下路径长度上限
max_candidate_pathsint1000heuristic 候选路径池大小
random_seedint42随机种子（用于 per-sample SP 抽样）
YAML 读写 
# 从项目 YAML 加载
config = RSPConfig.from_yaml("Cao_SOTA_MP/configs/beijing.yaml")

# 写出（可被 RSPConfig.from_yaml 重新读取）
config.to_yaml("my_config.yaml")

# 字典互转
d = config.to_dict()

3.3 RSPRunner — 实验运行

构造函数 
runner = RSPRunner(dataset, config)
runner.solve_case(...) — 单个 case 调试 
# 方式 A：用 od_idx（0 到 num_od_pairs-1）
case = runner.solve_case(repeat=0, od_idx=0, alpha=0.7)

# 方式 B：用具体的 origin/destination 节点 ID
case = runner.solve_case(repeat=0, origin=5, destination=9, alpha=0.7)
返回：RSPCaseResult 
print(case.tau)                         # float — 计算出的 deadline
print(case.ilp)                         # dict: {path_x, punctuality_prob, status, solve_time, ...}
print(case.milp)                        # dict: 同上（如果 config.methods 包含 MILP）
print(case.dijkstra)                    # dict: 同上（如果 config.methods 包含 Dijkstra）
print(case.metrics["methods"]["ILP"])   # dict: {punctuality_prob, correct, tie_aware_correct, objective_gap, ...}
runner.run(progress=True) → RSPResult — 批量实验 
# 遍历所有 (repeat × OD × alpha) 组合
result = runner.run(progress=True)   # progress=False 静默运行

print(len(result.df))                 # DataFrame 行数
print(result.df.columns.tolist())     # 列名列表
注意：run() 默认不写文件，只返回内存态 RSPResult。如需落盘，调用 result.save_csv(path)。

3.4 RSPResult — 批量结果读取

聚合访问器总览
方法返回说明
to_dataframe()pd.DataFrame完整结果副本
save_csv(path)None写 CSV 到磁盘
summary()pd.DataFrame按 method 的紧凑汇总：mean_punctuality_prob、tie_aware_accuracy、path_match_accuracy、mean_solve_time_s、optimal_rate 等
accuracy(metric)pd.DataFramemetric="tie_aware"：tie-aware 准确率；metric="path_match"：路径匹配准确率
method_comparison(ref)pd.DataFrame按 (repeat, od_idx, alpha) 对齐的 method-vs-reference 表（默认 ref=ILP）
solve_time()pd.DataFrame求解时间统计（mean/median/max/min）
status_counts()pd.DataFrame各 method 的 status 分布和占比
objective_gaps()pd.DataFrameobjective gap 聚合统计（p_ILP - p_method）
by_alpha()pd.DataFrame按 (alpha, method) 分组的指标汇总
by_od()pd.DataFrame按 (od_idx, method) 分组的指标汇总
worst_cases(method, baseline)pd.DataFramemethod 准时概率低于 baseline 的 case（默认 MILP vs Dijkstra）
save_figures(dir)None保存 tie_aware_accuracy_vs_alpha.png 到指定目录
关键指标说明
列名含义
tie_aware_accuracy主准确率：|gap| ≤ 1/N 即视为等效，N 为样本数。一个样本分辨率的容忍度。
path_match_accuracy辅助准确率：method 的边选择向量是否与 ILP 完全一致。更严格。
mean_objective_gapp_ILP - p_method 的均值。正值 = method 不如 ILP。
optimal_ratesolver 返回 "Optimal" 的 job 占比。
reference_available_rateILP 可作为 reference 的 job 占比（ILP 必须 Optimal）。

4. 完整使用流程

4.1 最小示例：从磁盘数据到结果

from rsp import RSPDataset, RSPConfig, RSPRunner

# 1. 加载数据
dataset = RSPDataset.from_directory("Cao_SOTA_MP/data/small")

# 2. 配置
config = RSPConfig(
    methods=("ILP", "Dijkstra"),
    alphas=(0.5, 0.7, 0.9),
    num_repeats=1,
    num_od_pairs=2,
)

# 3. 运行
runner = RSPRunner(dataset, config)
result = runner.run(progress=True)

# 4. 读取结果
print(result.summary())
print(result.accuracy("tie_aware"))
print(result.method_comparison("ILP").head(10))

4.2 单 case 调试

# 不跑批量，只看一个具体 case
case = runner.solve_case(repeat=0, od_idx=0, alpha=0.7)

print(f"tau = {case.tau:.2f}")
for method, m in case.metrics["methods"].items():
    print(f"{method}: punct={m['punctuality_prob']:.4f}, "
          f"time={m['solve_time']:.3f}s, status={m['status']}")

4.3 从内存数据构建

import networkx as nx
import numpy as np
from rsp import RSPDataset, RSPConfig, RSPRunner

# 构建一个 4 节点的 diamond 路网
G = nx.DiGraph()
G.add_edge(0, 1); G.add_edge(0, 2)
G.add_edge(1, 3); G.add_edge(2, 3)

rng = np.random.default_rng(42)
W = rng.lognormal(mean=3.0, sigma=0.8, size=(500, 4))

dataset = RSPDataset.from_arrays(G, W, [(0, 3)])
config  = RSPConfig(methods=("ILP",), alphas=(0.5,), num_repeats=1, num_od_pairs=1)
runner  = RSPRunner(dataset, config)
case    = runner.solve_case(repeat=0, od_idx=0, alpha=0.5)

print(f"ILP status={case.ilp['status']}, punct={case.ilp['punctuality_prob']:.4f}")

4.4 不想跑 ILP？省略 reference 的用法

config = RSPConfig(methods=("MILP", "Dijkstra"))  # 不含 ILP
runner = RSPRunner(dataset, config)
result = runner.run(progress=False)

# reference_available 为 False，准确率为 NaN（不会输出伪值）
print(result.summary())
print(result.accuracy("tie_aware"))   # 所有 method 的 tie_aware_accuracy 为 NaN

6. 没有封装的方法（当前 limitations）

当前 SDk 没有提供那种"一行调用"的便利函数。
即不存在 solve("data/small", origin=0, dest=9, alpha=0.7, method="ILP") 这种直接返回结果的函数。
用户仍需要手动构造 RSPDataset → RSPConfig → RSPRunner → solve_case()（共 4 步）。

如果需要这种一键式 API，需要在 rsp/ 中新增一个 solve() 函数，内部处理 dataset 加载、deadline 计算和 solver 调用，对外只暴露 data_path + origin + dest + alpha + method。
