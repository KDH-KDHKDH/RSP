2.3 已验证正确的部分

  • 求解器接口一致 — ILP/MILP/Dijkstra 的 (network, W, origin, destination, tau) 签名完全相同，返回 dict 结构一致。
  • _path_match 实现 — 正确使用 np.array_equal 比较路径向量，正确处理 MILP 非最优时的 None 情况。
  • Big-M 推导 — M = max(W·1) 对于首尾>1的路径不适用，但当前ILP的M足够大 (1e6)，实用上无问题。
  • flow conservation — 关联矩阵 M 和 OD向量 b 的构造正确 (流入-流出 = b)。

3.2 meta.yaml 缺陷

meta.yaml 记录了 num_nodes, num_edges, num_samples, seed, travel_time_range 等参数，但不记录行程时间方差参数 (travel_time_std_ratio)。这意味着仅从 meta.yaml 无法确定该数据集是用哪个 CV 范围生成的——这是 Phase 4b 最关键的实验变量，却没有被记录。

建议: 在 data/generate.py 的 generate_data() 函数中将 travel_time_std_ratio: [min, max] 写入 meta.yaml，使每个数据集自包含其生成参数。

7. 版本控制

Git 仓库存在但从未提交: .git/ 目录存在，但 git log 返回 "does not have any commits yet"。没有 remote 配置。所有变更只能通过 change.md 追溯，无法使用 git diff/blame/log。这是当前最严重的工程缺陷。

影响:

  • 无法回滚到之前的状态
  • 无法查看某次变更的具体 diff
  • change.md 中记录的所有历史无法用 git 验证
  • 无备份 — 如果本地文件损坏，所有代码和历史永久丢失
