4. 根因分析：数据方差过低

4.1 行程时间生成分析

当前数据生成 (src/generator.py:35) 为每条边使用对数正态分布：

  • 均值: Uniform(10, 100)
  • 标准差: 均值 × Uniform(0.1, 0.4)
  • 变异系数 (CV) 中位数: 0.25
  • CV 四分位距: [0.19, 0.33]
  • CV 最大值: 0.41

这意味着：一条平均通行时间 50 秒的路段，其标准差仅 5-20 秒。大多数情况下，实际通行时间非常接近均值。

4.2 为什么会"退化"？

准时问题的核心挑战是：均值最短路径 ≠ 准时概率最高路径。这需要行程时间有足够的波动性。

打个比方：

  • 路径 A：平均 45min，但波动大（30~90min）
  • 路径 B：平均 50min，但波动小（40~60min）

如果 deadline 是 55min，路径 B 虽然慢但也更稳定，准时概率可能更高。Dijkstra 会选 A（均值小），但 A 不是最优。

如果方差很小，路径 A 和 B 的波动都很小，那均值最短路径（Dijkstra）几乎等价于最优路径。

当前 CV 设定的问题是：即使是最宽松的 CV=0.4 也只产生 40% 的相对波动，不足以制造"均值路径非最优"的困难场景。论文的实验设定虽然未公开，但从结果（Dijkstra 仅 60-70% 准确率）反推，其行程时间波动应该显著更大。

5. 修复方案

核心修复：增大行程时间方差。

方案：扩大 CV 范围

将 generator.py 的方差参数从 Uniform(0.1, 0.4) 改为 Uniform(0.3, 0.8)，使 CV 中位数从 0.25 提升到约 0.55：

7. 补充：求解器选型说明

HiGHS → SCIP 迁移

原计划使用 HiGHS 求解器（highspy 1.14.0，比 CBC 快 4.8 倍），但在多种子测试中发现严重的堆内存损坏 bug（double free / malloc(): invalid next size）。该 bug 确定性地在某些数据实例上触发，即使在完全隔离的子进程中也无法规避。

已迁移到 SCIP (pyscipopt 6.2.1)，通过 PuLP 的 SCIP_PY 接口调用。SCIP 是学术界公认的顶级开源 MIP 求解器，比 CBC 快 2.7 倍，稳定可靠。论文原用 CPLEX，SCIP 是最接近的开源替代。
